# opencode-tps

## Background

OpenCode exposes token counts but does not show model request throughput in its TUI. Starting the clock at the first output token overstates the speed users experience because it omits request startup and time to first token. Using message completion is also misleading because OpenCode completes tool-calling steps after tool execution.

## Goals

- Show a weighted tokens-per-second metric for the active OpenCode session.
- Keep metrics for different providers, models, and variants separate.
- Measure model API request time, including time to first token but excluding tool execution and inter-step wait time.
- Remain usable when reopening an existing session.

## Functional Requirements

### MVP

- [x] Render the session TPS summary in the OpenCode sidebar.
- [x] Group TPS by provider, model, and variant.
- [x] Count output and reasoning tokens as generated tokens.
- [x] Track request windows from model-step start through the final streamed output event.
- [x] Include request startup and time to first token.
- [x] Exclude tool execution and inter-step waiting.
- [x] Reconstruct approximate historical metrics from assistant creation and persisted output timestamps.
- [x] Exclude reverted messages from metrics while an undo is staged and restore them on redo.

### Future

- [ ] Persist precise per-step request windows across OpenCode restarts.
- [ ] Add optional display and token-accounting configuration.
- [ ] Add per-response TPS if OpenCode exposes a supported assistant footer slot.

## Non-functional Requirements

- Support OpenCode 1.18 or newer within major version 1.
- Avoid a separate SolidJS runtime so the plugin works in packaged OpenCode builds.
- Keep TPS aggregation deterministic and covered by unit tests.
- Do not perform network requests or collect telemetry.

## Architecture

`src/tui.ts` adapts OpenCode TUI events and renders the sidebar. `src/session-tps-state.ts` owns framework-independent request tracking and weighted aggregation. Event-derived samples replace historical estimates for the same assistant message. A staged revert filters both historical and event-derived samples at OpenCode's message boundary without deleting them, so redo restores the original metrics.

The session metric is:

```text
sum(output tokens + reasoning tokens) / sum(model request durations)
```

Each model step is one model API request. Its duration starts at `session.next.step.started` and ends at the latest matching text, reasoning, or tool-input end event. OpenCode emits step completion after tool execution, so that timestamp is deliberately not used. Time between model requests is also excluded.

## Glossary

- **TPS**: Tokens per second generated by the model.
- **Request window**: Time from model-step start to the final output-end event for one model API request.
- **Historical estimate**: TPS reconstructed from assistant creation and persisted text/reasoning part timestamps when precise stream events are unavailable.
